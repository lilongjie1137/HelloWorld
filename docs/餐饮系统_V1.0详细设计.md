# 多门店连锁餐饮系统 · V1.0 详细设计

> 版本：v0.1（设计阶段，未进入开发）
> 配套文档：《餐饮系统设计架构文稿》（总体架构）。本文聚焦 **V1.0 核心交易闭环** 的模块清单、数据库表结构、接口草案与边缘网关同步协议。

## 0. 已锁定决策（贯穿设计）

| # | 决策 | 对设计的影响 |
| --- | --- | --- |
| 1 | **全国统一价** | 价格挂在 SPU 上，**不需要门店价格覆盖表**；菜单仍支持「门店适用范围」 |
| 2 | **P1 预留会员/储值数据结构** | 本期建表（member/会员卡/储值账户/流水），功能在 P3 实现 |
| 3 | **品牌统一商户号** | 支付结算主体 = 租户(品牌)级，单一商户号 |
| 4 | **外卖：美团 + 饿了么** | P2 对接；P1 在订单 `source` 与商品映射上预留字段 |
| 5 | **每店一台迷你主机做边缘网关** | 点单/出单/现金收银走本店局域网，强离线保障 |
| 6 | **后端 Go（go-zero）** | 微服务 + 单二进制边缘网关，云边同语言共享模型 |

## 2. ER 总览（V1.0）

```
tenant 1─* store 1─* production_dept
store 1─* table_area 1─* dining_table
tenant 1─* employee *─* role(*─* permission)；employee.data_scope 限定门店

商品：
category 1─* spu
spu *─* modifier_group  (通过 spu_modifier_group)
modifier_group 1─* modifier_option
spu.production_dept_id → production_dept
spu *─* store (通过 spu_store 适用范围)

交易：
dining_table 1─* order  (一桌多单)
order 1─* order_item 1─* order_item_modifier (快照)
order 1─* bill 1─* payment
order_item.production_dept_id (快照) → 打印分组依据

打印/设备：
store 1─* printer ; printer *─* production_dept (绑定)
order ─→ print_job *─→ printer

预留：
tenant 1─* member 1─1 stored_value_account 1─* stored_value_txn
member 1─* member_card
```

## 3. 数据库表结构（MySQL 8，核心字段）

> 约定：所有业务表含 `id BIGINT PK`、`tenant_id`、`created_at`、`updated_at`；门店级表含 `store_id`。金额用 `DECIMAL(10,2)`。以下省略公共字段，仅列关键列。

### 3.1 基础 / 租户

```sql
tenant(id, name, code, status)                          -- 品牌/租户
store(id, tenant_id, name, code, address, status)       -- 门店
production_dept(id, tenant_id, store_id, name, type)    -- 出品部门 type:KITCHEN/BAR/COLD...
device(id, tenant_id, store_id, type, name, sn, status) -- 设备 type:POS/PRINTER/LABEL/KDS
```

### 3.2 员工 / 权限 / 交接班

```sql
employee(id, tenant_id, name, phone, login_name, pwd_hash, status)
role(id, tenant_id, name, code)
permission(id, code, name)                               -- 如 order:refund, item:changeprice
role_permission(role_id, permission_id)
employee_role(employee_id, role_id)
employee_store(employee_id, store_id)                    -- 数据范围:可操作门店
shift(id, tenant_id, store_id, employee_id,              -- 交接班
      open_time, close_time, open_cash, close_cash,
      total_cash, total_order_amount, status)
```

### 3.3 商品中心（全国统一价）

```sql
category(id, tenant_id, name, sort, parent_id)
spu(id, tenant_id, category_id, name, base_price,        -- base_price=全国统一价
    production_dept_type,                                -- 出品部门类型(用类型而非具体店部门,便于连锁统一)
    is_combo, is_weighable, image_url, status, sort)
modifier_group(id, tenant_id, name,
    group_type ENUM('SPEC','METHOD','ADDON'),            -- 规格/做法/加料
    select_type ENUM('SINGLE','MULTI'), required TINYINT)
modifier_option(id, tenant_id, group_id, name,
    price DECIMAL(10,2) DEFAULT 0,                        -- SPEC=绝对单价/ADDON=加价/METHOD=0
    is_default TINYINT, sort, status)
spu_modifier_group(id, tenant_id, spu_id, group_id, sort)
spu_store(id, tenant_id, spu_id, store_id, available)    -- 菜单门店适用范围
```

> 计价规则（统一价，规格绝对价）：
> - **选了规格(SPEC)** → 该规格选项的 `price` 作为该行的**绝对基准单价**（如大杯=15、中杯=12），SPU.`base_price` 此时不参与计价。
> - **未配规格**（如炒菜）→ 用 SPU.`base_price` 作为基准单价。
> - **加料(ADDON)** → 每个选项 `price` 为加价，累加。
> - **做法(METHOD)** → `price=0`，不计价。
> - 公式：`unit_price = (有规格 ? 规格.price : spu.base_price) + Σ(ADDON.price)`。
> **无门店调价表。**

### 3.4 桌台

```sql
table_area(id, tenant_id, store_id, name, sort)          -- 区域:大厅/包厢
dining_table(id, tenant_id, store_id, area_id, name,
    capacity, status ENUM('IDLE','OPENED','TO_CLEAN'),
    qr_code)                                             -- 桌贴二维码(P2扫码点单用)
```

桌台状态机：`IDLE →(开台)→ OPENED →(结账清台)→ TO_CLEAN →(清台)→ IDLE`；转桌=改 order.table_id；并桌=多桌指向同一主单/合并账单。

### 3.5 订单（下单即快照）

```sql
order(id, tenant_id, store_id, table_id, order_no,
    source ENUM('POS','MINI_APP','TAKEOUT'),             -- P1主要POS,预留小程序/外卖
    status ENUM('OPEN','ORDERED','SERVING','SETTLED','CLOSED','CANCELED'),
    people_count, total_amount, discount_amount, payable_amount,
    employee_id, opened_at, settled_at)
order_item(id, tenant_id, order_id, spu_id,
    spu_name_snap, category_snap,                        -- 名称快照
    spec_option_id, spec_name_snap,                      -- 规格快照
    unit_price, qty, amount, remark,
    production_dept_type_snap,                            -- 出品部门快照→打印分组
    item_status ENUM('PENDING','SERVED','REFUNDED'))
order_item_modifier(id, tenant_id, order_item_id,
    group_type ENUM('SPEC','METHOD','ADDON'),
    option_id, option_name_snap, price_snap)             -- 规格/做法/加料逐项快照
```

> 单价 = (有规格 ? 规格选项绝对价 : spu.base_price) + Σ(ADDON.price)；METHOD 不参与计价。改价/退菜走权限校验 + 审计。

### 3.6 收银 / 账单

```sql
bill(id, tenant_id, store_id, order_id, bill_no,
    total_amount, discount_amount, payable_amount,
    paid_amount, change_amount, status, cashier_id, settled_at)
payment(id, tenant_id, bill_id,
    pay_method ENUM('CASH','SCAN_GUN','MEMBER','AGGREGATE'), -- AGGREGATE聚合支付(P2)
    amount, trade_no, status, paid_at)
discount(id, tenant_id, bill_id, type, value, reason, operator_id) -- 折扣/抹零
```

### 3.7 打印 / 路由

```sql
printer(id, tenant_id, store_id, name, ip, model,
    proto ENUM('ESC_POS','TSPL'), type ENUM('RECEIPT','LABEL'), status)
printer_dept(printer_id, production_dept_type)           -- 打印机绑定出品部门类型
print_job(id, tenant_id, store_id, order_id,
    printer_id, production_dept_type,
    job_type ENUM('KITCHEN','BAR','LABEL','CHECKOUT','REFUND'),
    payload JSON, status ENUM('PENDING','SENT','PRINTED','FAILED'),
    retry_count, job_key UNIQUE, acked_at)               -- job_key保证幂等防重打
```

### 3.8 预留：会员 / 储值（P1 建表，P3 实现）

```sql
member(id, tenant_id, phone, name, wx_openid, level, status)
member_card(id, tenant_id, member_id, card_no, status)
stored_value_account(id, tenant_id, member_id, balance, gift_balance)
stored_value_txn(id, tenant_id, account_id, type, amount,
    balance_after, ref_order_id, remark)                 -- 充值/消费/赠送流水
```

## 5. 打印路由流程（时序）

```
POS下单 → 交易服务落库 order/order_item → 发事件 order.created
   → 打印路由服务:
       按 order_item.production_dept_type_snap 分组
       每组 → 查该店 printer_dept 绑定 → 生成 print_job(job_key=order+dept+seq)
       下发到门店边缘网关
   → 边缘网关:
       入本地队列 → 调用对应打印机(ESC/POS)
       成功 → 回执 PRINTED；失败 → 重试N次 → FAILED(收银端可补打)
```
鱼香肉丝(KITCHEN)→后厨打印机；珍珠奶茶(BAR)→吧台打印机，互不干扰。

## 6. 边缘网关同步协议（弱网/离线）

- **在线**：POS → 边缘网关(局域网) → 实时转发云端；打印任务云端下发，网关执行回执。
- **离线**：POS → 边缘网关本地落库（订单/收银流水/打印任务），打印照常；公网恢复后：
  1. 网关按 `order_no/操作序列` 幂等上行同步到云端；
  2. 云端去重合并，回传权威状态；
  3. 现金账以门店为权威源补录。
- **冲突**：同一订单以「单号 + 单调递增操作序号」幂等，重复提交丢弃。
- **升级**：网关单二进制，支持远程灰度升级 + 版本回滚。
