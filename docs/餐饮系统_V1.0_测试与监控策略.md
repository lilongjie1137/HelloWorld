# 餐饮系统 V1.0 测试与监控策略

## 1. 测试分层
| 层级 | 范围 | 工具 | 现状 |
| --- | --- | --- | --- |
| 单元测试 | 领域逻辑（计价/拆单/单号/金额）、关键 logic | `go test` | 已覆盖 `domain/pricing`、`domain/printing`、`common/idgen`、`common/money`、`common/response`、`edge/internal/printq`、`app/trade` 计价 logic |
| 迁移测试 | DDL up/down 全链路 | MySQL service | CI `migrations` job：up→verify(≥30 表)→down |
| 集成测试 | 服务 + DB + Redis | go-zero + docker-compose | 待业务 logic 落库后补充 |
| 端到端 | golden path 全流程 | 脚本/Postman | 见第 3 节 |

运行：`make test`（含 `-race`）；覆盖率：`make cover`。

## 2. 重点专项测试（餐饮生命线）
- **打印可靠性**：`edge/internal/printq` 已测幂等防重打、失败重试、重试耗尽、打印机缺失。
  后续补充：打印机离线→恢复后补打、并发多任务顺序。
- **离线/弱网兜底**：`edge/internal/offline` + `sync` 的「断网本地落库 → 恢复幂等上行」需加集成测试，
  模拟云端不可达、重复上行、序号乱序。
- **拆单路由**：`domain/printing` 已测「鱼香肉丝→后厨、珍珠奶茶→吧台」拆分与未绑定部门上报。

## 3. V1.0 验收 Golden Path
1. 登录（admin/admin123）→ 开班。
2. 开台（1 号桌）。
3. 混合点单：鱼香肉丝×2 + 大杯珍珠奶茶（加珍珠/去冰/半糖）×1 → 合计 **74.00**。
4. 自动拆单：后厨打印机出鱼香肉丝、吧台打印机出奶茶，互不干扰。
5. 结账：现金/扫码，找零正确，账单 `PAID`，桌台 `TO_CLEAN→IDLE`。
6. 退菜补打、反结账（按第一类决策定稿后纳入）。
7. 交接班：现金汇总与差异记录。
8. 断网演练：拔网线后第 2–5 步仍可完成，恢复后云端对账一致。

## 4. 监控与日志骨架
- **日志**：go-zero 内置 `logx`（结构化、按级别）。约定每条业务日志带 `traceId / tenantId / storeId`。
- **链路追踪**：go-zero 集成 OpenTelemetry，配置 `Telemetry` 上报到 Jaeger/OTLP（部署时开启）。
- **指标**：go-zero 暴露 Prometheus 指标（QPS/延迟/错误率），按服务采集。
- **关键业务告警（待接入）**：
  - 打印任务失败率 / 重试耗尽数；
  - 边缘网关离线时长（`6002`）；
  - 支付回调失败、结账金额不符（`5002`）。
- **边缘网关**：本地滚动日志 + 心跳上报云端，远程查看在线状态与版本（远程升级 P2）。

## 5. CI 门禁
`.github/workflows/ci.yml` 三个 job 均为合入 `main` 的必过项：
1. `build-test`：`go vet` + `go build` + `go test -race`（带覆盖率）。
2. `lint`：golangci-lint v1.64.8。
3. `migrations`：MySQL 上跑迁移 up/down 全链路。
