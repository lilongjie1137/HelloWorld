## 3. 单号规则 ✅
对应 `common/idgen`。格式：`{业务}-{门店码}-{yyyyMMdd}-{4位日序号}`。

| 业务 | 前缀 | 示例 |
| --- | --- | --- |
| 订单 | `O` | `O-SH001-20260530-0007` |
| 账单 | `B` | `B-SH001-20260530-0003` |
| 打印任务 | `P` | `P-SH001-20260530-0021` |

- 序号在「业务+门店+自然日」维度内单调递增、每日归零。
- 离线场景：边缘网关用门店本地序列生成，门店码前缀天然防跨店冲突，上行云端按单号幂等去重。
- 打印任务幂等键 `job_key = {orderNo}:{deptType}`（见 `domain/printing`），防止重复打单。

## 4. 计价模型 ✅（已锁定：规格绝对价）
对应 `domain/pricing`。金额一律以「分」计算。

```
unitPrice = (有规格 ? 规格选项.price : spu.base_price) + Σ(加料选项.price)
amount    = unitPrice × qty
```
- SPEC（规格）：选项 price 为**绝对单价**（大杯=15.00），覆盖 base_price；必选时未选报 `3002`。
- ADDON（加料）：每项累加（加珍珠=+3.00）。
- METHOD（做法）：不计价（去冰/半糖/免葱=0），仅做合法性校验与快照。
- 校验：选项必须归属该 SPU 的属性组；SINGLE 组多选报 `3003`；重复选项报错。
- 已验证用例：大杯奶茶+加珍珠=18.00；鱼香肉丝×2=56.00；混合单合计 74.00（见 `app/trade` 逻辑测试）。

## 7. 桌台 / 订单状态机 ✅
- 桌台：`IDLE → OPENED → TO_CLEAN → IDLE`（对应 `common/types.TableStatus`）。
- 订单：`OPEN → ORDERED → SERVING → SETTLED → CLOSED`，可 `CANCELED`（对应 `OrderStatus`）。
- 明细：`PENDING → SERVED`，可 `REFUNDED`。
- 账单：`UNPAID → PAID`，可 `REVERSED`（反结账）。
